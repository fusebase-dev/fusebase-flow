# v5.8 — token audit sees the whole run; guidance against the real cost drivers

> **Drop-in from v5.7.** Nothing to configure, and no hook, approval, gate or role-boundary
> change. Upgrade as usual with `bash hooks/local/upgrade.sh`.

Three teams ran `/token-waste-audit` on long Claude Code sessions and found that it pointed at the
wrong things. We measured all three runs ourselves. Sub-agents were 77–84% of the cost and the audit
never read them. Every "large output" it flagged was a screenshot counted as text. The real cost sat
in agents whose context grew past 500k tokens, and in rebuilding that context after the prompt
cache had expired. This release fixes the audit and changes the guidance that pushed runs that way.

## `/token-waste-audit` now shows where the cost went

| Before | Now |
|---|---|
| Read the main session only | Also reads sub-agent and workflow-agent transcripts (`--main-only` keeps the old scope) |
| Sized screenshots by their base64 text | Counts images separately with a dimension-based token estimate; flags the same image read twice |
| Opened with per-call candidates | Opens with an estimated cost by category: main vs sub-agents × cache read / cache write / output |
| No signal for long contexts | Lists the transcripts whose context peaked past 500k and their share of the cost |
| No signal for cache expiry | Flags requests that rewrote the cache after a gap longer than its lifetime (1 h or 5 min) |
| One noisy session could print hundreds of rows | At most 10 rows per class per session, plus "N more suppressed" |

Costs are list-price estimates from a dated rate table; requests from an unknown model are counted
in tokens and listed as unpriced, never guessed. The report still contains no message, tool-result
or image content.

## New guidance (`token-economy` TE-19–TE-21 and the skills that carry it)

- **Bounded context (TE-19).** Plan delegated work so each worker finishes in about 50 tool calls;
  split bigger work into task groups, each started fresh from the records. A worker gets its own fix
  back only while it is still small; otherwise a fresh worker picks it up. This is a split point, not
  a token cap.
- **Wait under the cache lifetime (TE-20).** A waiting agent wakes on an event, or checks at least
  every 4 minutes with a bounded check loop (never a bare leading `sleep`, which Claude Code blocks).
  Sub-agents have a 5-minute cache, so a longer silent wait rewrites their whole context. The fixed
  60–90 s liveness poll now applies only to an agent that never started.
- **Screenshots (TE-21, `smoke-testing`).** Compare captures by script and read only what it flags,
  once each unless re-captured, cropped to the region in question. The capture a verdict rests on is
  always viewed.
- **Fresh session at a milestone (FR-17).** Offering to continue from the handoff in a fresh session
  at a milestone now counts as moving forward, not as stopping. The agent offers once, after a
  compaction or 3 closed outcomes, beside the next action; you open the session; no reply means it
  carries on here.
- **Sub-agent start-up.** One canonical start-up text for delegated workers. `AGENTS.md` is read
  unless its Flow section is already in context — a host can load only part of it (Codex reads the
  first 32 KiB by default).
- **Operator settings, documented not defaulted.** When the audit shows a long main session,
  Claude Code's `autoCompactWindow` (or `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, plain integer such as
  `500000`) compacts earlier. A 1-hour cache for sub-agents is not recommended: it raises the cost of
  every write more than it saves.

## Unchanged

- No hard token budgets or caps anywhere; quality still outranks tokens.
- Role boundaries, approvals, gates and the deploy contract are unchanged.
- FR-17 still forbids suggesting closing, resting or postponing.
