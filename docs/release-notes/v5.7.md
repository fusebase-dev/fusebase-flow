# v5.7 — model-routing example refreshed to current models

> **Drop-in from v5.6.** Nothing to configure, and no hook, approval, gate or role-boundary
> change. Upgrade as usual with `bash hooks/local/upgrade.sh`.

## Changed: the model-routing worked example

`policies/model-routing.yml` carries a commented example of one operator's actual setup. It still
named that operator's older models (Opus 5, Sonnet 5, Haiku 4.5). It now shows:

| Work | Model (exact id) | Effort |
|---|---|---|
| Planning | Opus 5.5 (`claude-opus-5-5`); Fable 5.1 for real decisions | extra-high |
| Adversarial review | GPT-6 Astra (`gpt-6-astra`); backup GPT-6.1 Sol (`gpt-6.1-sol`) | high |
| Sensitive and routine implementation, execution | Opus 5.5 (`claude-opus-5-5`) | high |

Effort is a session setting, so the example states it in comments, not as a key.

## Unchanged

- The five shipped rows are still `null`: Flow names no model, and `/step-out` runs on your
  host's current model unless you fill the rows in yourself.
- The example is not a default or a recommendation.

If you copy the example, check every id against your own provider first. `gpt-6.1-sol` needs
Codex CLI 0.160.0 or later.
