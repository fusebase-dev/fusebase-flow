# v4.15.0 — recovery safety with bounded workflow evidence

Full entry: `CHANGELOG.md` § [4.15.0]. This note records the release boundary and upgrade guidance.

This release gathers the recovery, evidence, and workflow hardening completed since v4.14.1. It closes
the performance-and-recovery hardening roadmap without treating local focused checks as published
release evidence.

## Upgrade guidance

For a routine Fusebase CLI refresh, use:

```bash
fusebase update --skip-skills
```

If a full `fusebase update` replaces provider-managed files, restore Flow's overlay and previously
authorized wiring with:

```bash
bash hooks/local/post-fusebase-update.sh
```

Automatic Git-hook restoration now requires prior installed-hook or receipt ownership proof. Use
`bash hooks/local/post-fusebase-update.sh --wire-hooks` only when explicitly activating Flow hook
wiring. Recovery preserves consumer and CLI-owned content and refuses ambiguous ownership or malformed
overlay structure instead of manufacturing a clean result.

## Recovery boundary in detail

Recovery now separates intent, ownership, preparation, apply, and verification:

- It creates missing-and-authorized targets, repairs owned targets with retained originals, and leaves
  current targets unchanged. Source identity, target type/ancestry, and exact classified bytes or
  absence are rechecked immediately before apply.
- A portable lock coordinates cooperating recovery writers, and changed rows are preserved under the
  reviewed same-process/coordination model. No protection against arbitrary hostile same-user mutation
  is claimed.
- Settings merge repairs the dedicated Flow handler by exact type, count, matcher coverage, and block
  scope while preserving consumer block order and producing a byte-stable second merge.
- Hook auto-restoration requires prior Flow ownership proof. Explicit `--wire-hooks` is still an
  operator-authorized activation.
- Unresolved external settings loss persists across retries until verified restoration or explicit
  disposition. Every applicable overlay marker/span is validated before any target write.
- Inline or backticked ownership-marker examples remain provider prose. Only exact standalone marker
  lines delimit spans, and a recognized adapter heading must belong to a successfully parsed span.
- Final verification compares the pinned canonical overlay, preserved external bytes, exact allowed
  surface identifiers, and CR-normalized transport rather than accepting command presence alone.

## Evidence and performance limits

The focused roadmap evidence is recorded in the ticket gate and includes mutation controls for ignored
inputs/environment, settings wiring, concurrent recovery edits, receipt union, malformed markers, and
temporal linkage. Historical no-op recovery evidence completed three calls under 45 seconds with zero
target changes or retained copies after cleanup; selector and manifest work also reduced repeated test
setup. Environment cleanup and fixture changes mean those observations do not establish a universal
end-to-end speedup. T57 makes long health stages visible on stderr; it changes no stage runtime and
makes no runtime-speedup claim.

**Validator reuse is globally disabled.** Caller-provided `schema=1`, `complete=true`, and dependency
arrays cannot independently prove complete capture, so real validators run on every platform. This
release therefore claims **no lint/typecheck skip benefit**.

## Tagged-SHA publication evidence

The scoped local gate is complete, but it is developer evidence only. Publication requires all of the
following evidence on the exact tagged SHA:

- the tagged-SHA Linux CI job;
- the tagged-SHA Windows/MSYS CI job; and
- the repository verify gate on that same tagged SHA.

Until those checks pass, this note does not claim publication or two-platform release evidence.

## Deferred Fusebase CLI compatibility evidence

An actual current Fusebase CLI install, update, and recovery exercise remains deferred/unverified
compatibility evidence under the final ticket gate. It is outside the approved local completion
boundary and is not tagged-SHA publication evidence. Real symlink/MSYS/Linux and Windows authority
beyond the recorded local fixtures likewise remain deferred/unverified.
