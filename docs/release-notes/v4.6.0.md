# Fusebase Flow v4.6.0

## Session boot floor: 78,148 → 41,321 bytes (a 47.1% cut)

Every Flow session paid a fixed boot floor before any work started. A consumer ran
the framework's own `/token-waste-audit` across 5 sessions (7,175 requests, ~9.0M
output tokens) and escalated: the mandatory always-on artifacts were the single
largest redundant cost, and short sessions paid the worst ratio — the smallest
audited session spent more on floor reads than on its actual task.

This release cuts that floor and fixes five compounding defects around it.

### The measurement (all sizes are bytes, `wc -c`)

| Artifact | Before | After | Ceiling |
|---|---:|---:|---:|
| `flow-skills/communication/SKILL.md` | 19,936 | 6,867 | 7,000 |
| `flow-skills/role-discipline/SKILL.md` | 29,089 | 14,167 | 14,500 |
| `FLOW_RULES.md` operative section | 19,962 | 11,126 | 11,500 |
| largest `role-discipline/references/<role>.md` | 9,161 | 9,161 | 9,200 |
| **Role-aware boot floor (worst case)** | **78,148** | **41,321** | **42,200** |

**78,148 → 41,321 bytes is a 47.1% cut.** Not "about half", not rounded up — that
is the measured number, and the ceilings are enforced by
`hooks/tests/test-boot-size.sh` (22/22, including 9 red arms and an arithmetic
guard proving the per-artifact ceilings sum to the stated total).

Note that the *pre-change* figure the escalation quoted (a three-artifact floor of
68,987 B) understated the real cost: it missed the per-role
`references/<role>.md` file that `role-discipline/SKILL.md` requires the attested
role to read. The honest starting point is 71,802–78,148 B depending on role.

### The escalation asked for ≤5k tokens. That was arithmetically impossible.

We are saying this plainly rather than quietly shipping a smaller number.

The operative `FLOW_RULES.md` alone was 19,962 bytes ≈ **5k tokens on its own** —
before either mandatory skill, before the role reference. Hitting a ≤5k-token
total would have required deleting rule statements, moving the FR-24 write-time
digest to a lazy file, or collapsing the role don't-lists. All three are forbidden:
FR-24's entire thesis is that those rules only work when they are in context *at
write time*, and a prohibition parked in a lazy file is not a rule.

So the target was reset to a byte budget derived by summing the components that
are genuinely non-negotiable, and the ceiling was amended three times as
correctness demanded room. **Correctness outranks the byte budget.** The result is
a 47.1% cut, not the ~70% the escalation implied.

### Lazy content is re-tiered, not deleted

Total framework content did **not** shrink. Elaboration, worked examples, and
recovery procedure moved from the always-on files into `references/` files that
load only when a session actually needs them — most notably
`flow-skills/role-discipline/references/shared-protocols.md` (**21,233 B**) and
`flow-skills/communication/references/mode-b-detail.md`. A session that opens a
protocol body pays those bytes on top of the 41,321-byte floor.

What moved is *elaboration only*. Guarded by:

- **AC2 rule inventory** (`hooks/local/rule-inventory.sh`) — 170 rows, each
  `ID + normalized text + canonical source path + resident|lazy`. A rule that
  moved resident→lazy, or a don't-list row that moved between roles, is a
  non-empty diff by construction. An earlier two-column version of this
  instrument reported CLEAN on exactly that kind of loss; the residency column
  exists because of it.
- **AC3 / `test-prohibition-residency.sh`** — no `references/*.md` file may carry
  a normative marker (`MUST`, `never`, `do not`, `forbidden`, `STOP`, `refuse`,
  an exact-refusal-phrasing block) without a resident counterpart in its
  `SKILL.md`. Red arm proven by planting a marker.

Zero FR rules, zero role don't-list rows, and zero FR-24 digest rows were removed
or moved out of always-on residency.

## `FLOW_RULES_HISTORY.md` — the rule that protected the file lived inside it

`FLOW_RULES.md` carried its dated amendment log inline: ~62% of the file, and the
"never load the Amendment log" instruction sat *inside the section it was
protecting*. You had to read it to learn not to read it.

The log now lives in a root-level `FLOW_RULES_HISTORY.md`. `FLOW_RULES.md` keeps a
compatibility `## Amendment log` stub heading with a ≤2-line pointer, so every
stop-at-heading consumer and the `sync-version-strings.sh` range anchor keep
working unchanged. The extracted content is content-equivalent except a normalized
final newline (the extraction added one LF — we test that exact contract rather
than claim "byte-preserved", which would have been false).

History is distributed, not orphaned: CI public-surface allowlist,
`PUBLISHING.md`, `upgrade.sh` `CONTENT_FILES`, `protected-paths.yml`, and
`agent-surface-ownership.json` all admit it, and `test-sync-allowlist.sh`
classifies it as dated history so it is never version-synced (it contains
live-looking FR and version strings).

## Anti-reread — with its premise honestly narrowed

The escalation's F2 finding was that mandatory skills get re-`Read` after being
auto-injected, so sessions pay for them twice. Both mandatory skills now carry an
exact-body anti-reread rule.

**But the premise was wrong in an important way, and we verified it first-hand
rather than shipping the claim.** On Claude Code and Codex, skill *descriptions
and metadata* are injected — **bodies are not**
(`hooks/handlers/session_start.py` existence-checks and emits reminders; it never
injects a body). So the measured "double-pay" was largely sessions reading bodies
that **were never auto-injected in the first place**. That is a floor cost, not a
duplication cost — and the floor cut above is what addresses it.

The anti-reread rule still pays off, on genuine within-session re-reads. It is
worded so that description/metadata discovery does not count as "already loaded",
and every "do not re-Read" instruction is conditioned on an actual body-presence
check, **never on a surface name**. The per-surface auto-load matrix was corrected
across all five provider surfaces; no row may claim eager body loading unless a
fresh-session test proves it. Getting this wrong in the other direction would tell
a non-auto-loading surface that it auto-loads, and the mandatory skill would never
load at all.

## Also in this release

| Area | What |
|---|---|
| Delegated report budget | Sub-agent **chat returns** capped at ≤80 lines **and** ≤6,000 chars (a single 32k-char line passes a line-only gate). Overflow goes to a durable artifact. Canonical gate reports and deploy reports are explicitly **exempt** — evidence completeness outranks the cap. Measured trigger: delegated returns reached 32,164 chars × 11 ≈ 88k tokens. |
| Supersede vs. write primitive | FR-18, `role-discipline § Supersede Convention`, `handoff`, and `token-economy` TE-06 now state both dimensions without contradiction: *replace stale semantics; patch unchanged structure*. Targeted `Edit` is the default; full `Write` is for structure/mode/ticket changes. The old "write fresh" wording nudged whole-file rewrites where an edit would do. |
| `token-waste-audit.py` | Growing-source-tail and possible-FR-10-triple candidates are now **auto-classified with a visible labeled line** stating the rule that fired and the evidence that triggered it. Silent dismissal is forbidden; dismissals are counted in a section separate from live findings; the report distinguishes *candidates found*, *all auto-classified*, and *no transcripts / parse failure* in words. Probe matching is verb-anchored (a bare `\bstatus\b`-anywhere match auto-dismissed `echo status` ×3) and read keys are path-canonicalized (`C:/Repo/a.txt` vs `c:\repo\a.txt` were treated as unrelated). |
| Zero-trust delegated liveness | FR-27 now states the delegate-retry envelope explicitly: max 3 attempts / 5 minutes, labeled backoff, then successor-or-`blocked-at-delegate-no-start`. Every unqualified "retry until it starts" was removed from all carriers — an unbounded retry is exactly the un-observable background work FR-27 exists to prohibit. |

## How this was verified — and what the gate did not catch

`hooks/tests/run-tests.sh` **619/619, 0 FAIL, 0 INCONCLUSIVE**. Preflight 0 errors,
hook manifest 121/121 MATCH, mirrors 0 drift, module-size clean, health check
HEALTHY. Final gate: **28/28 acceptance criteria PASS**.

**The gate alone was not sufficient, and that is worth stating.** An earlier gate
run on the first implementation passed **537/537 tests with 23/23 acceptance
criteria evidenced**. An independent adversarial review (Codex 5.6-Sol, High) run
*after* that passing gate then found **six BLOCKERs** plus nine further findings —
all fifteen accepted:

| # | BLOCKER found after the gate passed |
|---|---|
| 1–2 | Shared-protocol prohibitions and six Mode-B principle normative clauses had been moved into lazy `references/` files. The rule text still existed, so the then-current inventory diffed clean. A prohibition you have to opt into loading is not a prohibition. |
| 3–4 | The per-surface auto-load matrix claimed body injection that does not happen — the F2 correction above. |
| 5–6 | Two classifier false negatives in `token-waste-audit.py`: unanchored `status` substring matching, and raw-string path comparison that treated `C:/Repo/a.txt` and `c:\repo\a.txt` as unrelated files. |

A second gate run then failed three more acceptance criteria (a missing
`### Write primitive` section, five surviving unbounded-retry statements, and a
test that had drifted past its timeout as the repo grew) before reaching PASS.
Each finding is now locked by a regression arm with a proven red state, including
`test-prohibition-residency.sh`, the residency-aware rule inventory, and
`test-budget-literals.sh` — which caught a budget amendment that half-landed in
prose the instant the enforced ceilings moved.

## Upgrading

No action required beyond the normal upgrade path. `FLOW_RULES_HISTORY.md` is a new
root-level content file and ships automatically via `hooks/local/upgrade.sh`.
Nothing was removed from the rule set — if you have local references to
`FLOW_RULES.md § Amendment log`, the stub heading still resolves.
