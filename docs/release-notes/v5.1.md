# v5.1 — two-part versioning, plus gate and test-harness hardening

> **Drop-in from 4.17.1.** This release carries no runtime behavior change beyond what
> 4.16.x–4.17.1 already delivered. The large jump in the version number is a deliberate
> re-versioning, not a signal that your tree behaves differently — see below.

## New version scheme: `MAJOR.MINOR`

From **v5.1** Fusebase Flow versions are two-part `MAJOR.MINOR` and drop the patch component.
Releases will look like `5.1`, `5.2`, `6.0` — tagged `v5.1`, `v5.2`, `v6.0`.

The jump from 4.17.1 to 5.1 consolidates the approval-binding command-authorization cutover
(shipped in 4.17.0 and published in 4.17.1) into a clean major line and drops the third version
component going forward. Nothing about the format change alters how your installed tree runs;
`VERSION` is still the single source of truth and every carrier tracks it. Historical three-part
version strings (in older docs and consumer trees) are still recognised — nothing you hold needs
re-labelling.

## Fixes that reach your own gate

- **The test suite no longer needs a bare `python` on your PATH on Linux.** It runs the resolved
  interpreter it was launched with, so a system where only `python3` exists no longer breaks a
  consumer's own gate run.
- **A killed gate no longer leaves orphan processes behind on Windows/MSYS.** The phase group the
  harness actually spawns is now reaped when a run is stopped, instead of leaking child processes.

## Wider gate coverage

The essential release profile now runs three more phases:

- `signal-reap` — process-lifecycle owned-child cleanup.
- `health-check-timeout` — health-check timeout propagation.
- `preboundary-consumed` — the hardest upgrade route.

These were reviewed and promoted into the release profile so the routes they cover are now gated
on every tagged release rather than only run on demand.

## Internal (no consumer-facing behavior change)

- Gate-bounds cost is now attributed with measured phase timings. **No wall time was changed.**
- A git-context test oracle was corrected.
- The convergence catalog gained a self-created-regression discriminator.
- A proposed drift-checkpoint rule (FR-28) was reviewed and **declined**, in favor of two edits to
  the existing correction-review step.

The `health-check-timeout` (m9) work was a **test-fixture repair**, not a fix to any path
consumers exercise — consumers were not affected by the fixture defect it corrected.

## Known, not yet scheduled

- A damaged consumer `hooks/shared/` could cause approval collection to fail silently. The same
  corruption is separately caught by manifest-integrity checks, so it does not pass unnoticed
  overall; a dedicated loud error for the damaged-`shared/` case is filed as a future item
  (`docs/backlog/approval-collection-fails-silent-on-damaged-shared`).
