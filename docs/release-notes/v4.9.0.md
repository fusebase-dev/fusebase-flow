# v4.9.0 — consumer escalation

Full entry: `CHANGELOG.md` § [4.9.0]. This file records release evidence and the upgrade note.

## Upgrade note

| Change | Effect on you |
|---|---|
| A resolved `python3` must now prove it is ≥3.10 | Previously only the `python` / `py -3` fallbacks were checked, so a `python3` on `PATH` was trusted unverified. If yours is older, the commit is refused with a fixable message. `python3 -S -c` support is NOT required — a wrapper that only handles `-S <file>` still works. |
| A broken or missing `git` inside a repository now BLOCKS | Previously it exited 0 and silently skipped the secret scan and protected-path check. Genuine outside-a-repository execution still exits 0 unchanged. |
| Deploy reports embed an approval receipt | The committed report no longer cites a gitignored path. The live approval is unchanged and still gates the deploy. |

Nothing requires action on upgrade. No migration, no config change.

## Identify which tree you have

`docs/release-fingerprints.md` maps every released tree to its manifest fingerprint. Two rows share
`VERSION` 4.7.0 because that tag was moved; the fingerprint tells them apart. If
`audit/managed-content-manifest.json` is missing on your install, use the documented hook-layer
fallback — that file is absent on repositories upgraded by a pre-4.7.0 engine (finding F1).

## Known residuals

Carried deliberately and stated rather than omitted:

- The command gate still denies honest prose quoting a destructive pattern. Only the diagnostic
  improved; the matching is unchanged and remains blocked on decisions K21/M8.
- Tag immutability is enforced by operator confirmation, not by a repository ruleset. A human gate
  cannot stop a tag moved directly on the hosting platform or by an automation that never asks.
- Nothing in this release authenticates git, the interpreter, or the operator. A caller who controls
  `PATH` can still supply a shim; the receipt shows an approval was validated, not who approved it.
- `docs/release-fingerprints.md` gains its `v4.9.0` row after this tag exists — the fingerprint is
  computed from the tagged tree, so it cannot be inside the tree it describes.
