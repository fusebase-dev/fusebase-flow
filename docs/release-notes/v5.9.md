# v5.9 — fixes from a FuseBase CLI update escalation; v5.8 follow-ups

> **Drop-in from v5.8.** Nothing to configure. One new approval rule (below). Upgrade as usual with
> `bash hooks/local/upgrade.sh`.

A team running `fusebase update` in a Flow project hit four Flow problems in one day. This release
fixes all four and closes the open items left by v5.8.

## Fixed

| Problem you may have seen | What changed |
|---|---|
| The CLI's pre-update checkpoint commit staged `policies/model-routing.local.yml` or a Claude Code worktree under `.claude/worktrees/`, and Flow's pre-commit then blocked the commit | Flow now adds `/policies/*.local.yml` and `/.claude/worktrees/` to `.git/info/exclude` on every upgrade and post-update run, so `git add -A` never stages them. Your `.gitignore` is not touched. The install guide's snippet now uses the `policies/*.local.yml` glob |
| `post-fusebase-update.sh` changed nothing yet printed "Recovery uncertainty" | Without `--refresh-overlays`, the check now compares against the file as it was before the run. A line-endings-only difference is reported as an advisory with exit 0, telling you which lines and that `--refresh-overlays` normalises them. A real content difference is still reported. On Windows the heading update no longer rewrites every line ending in `AGENTS.md` |
| The secret scan blocked a commit because a URL slug such as `…task-action-…` looked like an OpenAI key | The OpenAI, Anthropic, GitHub, GitLab, AWS key id and Google OAuth patterns now match a key that starts at a word boundary, or one glued to other text whose body has a digit and an uppercase letter. A new release-gated test covers key shapes, contexts and slug false positives |
| `approve-local.sh` refused to create an approval for `fusebase isolated-store sql bundle --apply` | That command now needs a `database_migration` approval in every environment, like other migration tools, so an approval can be created for it. Read-only variants (`--dry-run`, `--status`, `--json` …) are unaffected |

## New approval rule

`fusebase isolated-store sql bundle … --apply` requires a `database_migration` approval. If your agents
run FuseBase migrations, approve them in chat as you do for other migrations.

## Smaller changes

- Delegated workers report whether they compacted and how many tools they used; a fix goes back to the
  same worker only while it is still small.
- The cache-lifetime guidance (TE-20) gives the break-even for each model's cache-read price.
- `/token-waste-audit` measures gaps from when a request was sent (it catches cache rewrites a long
  previous answer used to hide), counts polling repeats correctly, and marks which costs are observed
  and which are estimated.

## Known limits

- The secret patterns can miss a key glued directly to a preceding word when the key has no digit or no
  uppercase letter (roughly 3% of AWS and GitLab keys in that position; keys after a space, quote, `=` and
  so on are always caught).
- The CLI-side issues from the same report (checkpoint staging untracked files, an SDK pin widened to a
  lower range, CRLF carried into `AGENTS.md`) belong to the FuseBase CLI.
