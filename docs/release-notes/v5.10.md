# v5.10 — test-run cleanup that works on Windows; small follow-ups

> **Drop-in from v5.9.** Nothing to configure, and no rule, approval, gate or role-boundary change.
> Upgrade as usual with `bash hooks/local/upgrade.sh`.

## Fixed: leftover test processes after a killed test run on Windows

When a test run is killed (an outer timeout, or Ctrl-C), a small watcher is meant to stop the run's
child processes. On Windows (Git Bash/MSYS) it only noticed the run had died once the run's parent
process had collected it — which could take many seconds or never happen — so the children could keep
running and slow down every later run. The watcher now notices the exit itself.

**Guarantee:** the watcher acts within one poll of the test run exiting (about 1–2 s on an idle
machine), whether or not its parent has collected it. On GitHub's Windows runner it now detects the
exit in 29–622 ms and leaves no processes behind.

The release check for this guarantee (`signal-reap`) also got sturdier: it gates on what the watcher
did (detection within two of its own polls; no child left alive when it finishes) instead of
wall-clock limits that a busy machine could miss.

## Smaller changes

- `task-delegation`: without a reliable tool-use count, a worker gets its own fix back only within the
  one task group it was given; a return without the context field goes to a fresh worker.
- Test-only hardening: the secret-pattern matrix rejects every open-ended lookahead quantifier; the
  token-audit fixtures pin the request-start reset; clearer comments in `post-fusebase-update.sh`.
