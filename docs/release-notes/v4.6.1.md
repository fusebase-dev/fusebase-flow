# Fusebase Flow v4.6.1 — release notes

**Date:** 2026-07-26
**Type:** patch (hotfix — red `main`)
**Supersedes:** v4.6.0

## Summary

v4.6.0 was tagged and pushed with a recorded **619/619 local green**, and both CI workflows went red on arrival. This patch fixes the two defects in `hooks/tests/test-sync-allowlist.sh` that made `fusebase-flow-verify` fail at the "Hook tests (deterministic fixtures)" step (`fusebase-flow-release` failed only because its publish job is gated on verify — the [[ci-red-invisible-no-release-gate]] guard working as designed).

**No product behavior changed.** The framework's runtime, hooks, policies, skills, and workflows are byte-identical to v4.6.0 apart from the version strings. The only functional change is inside one test file.

## The failure was NOT platform-specific

The entry hypothesis was Windows-passes / Linux-fails divergence — plausible, because [[ci-linux-msys-test-divergence]] is exactly that. It was wrong. At the pushed commit the suite fails **identically on MSYS and on `ubuntu-latest`**:

| Commit | Platform | `test-sync-allowlist.sh` |
|---|---|---|
| `4323b23` (HEAD~1) | ubuntu-latest | 7/7 PASS |
| `9b62819` (pushed) | ubuntu-latest | **5/7 PASS** |
| `9b62819` (pushed) | Windows/MSYS | **5/7 PASS** — byte-identical failures |

Full suite on `ubuntu-latest` at `9b62819`: **614/616**, preflight 0 errors / 0 warnings, and these two assertions are the **only** failures.

The 619/619 was real — for a tree that was never published. It was measured at or before the release commit `ef7793e`; two further commits (`4323b23` docs closeout, `9b62819` ROADMAP + backlog note) landed **after** the verification gate ran.

## Root cause

`9b62819` added `docs/backlog/rule-inventory-version-literal-noise/README.md`, a backlog note that quotes the self-attestation string **verbatim as an illustration** of the version-literal noise it describes. Two latent defects then fired:

### 1. An enumerated record-tree exclusion that named a path this repo has never had

`test-sync-allowlist.sh` derives the TRUE set of framework files that must carry a live, synced version string by walking the repo and grepping content, then prunes record/consumer doc trees **by enumerated name**. The enumeration listed `./docs/product-backlog` — the **consumer** layout name, absent from this repo's entire history — and never listed this repo's own `docs/backlog`. Backlog notes therefore defaulted to "framework file", and the under-reach guard correctly flagged a dated record as an unsynced framework file the moment one first quoted a live token.

An enumerated exclusion **fails open** for every doc tree nobody remembered, and nothing distinguished a dead entry from a live one.

### 2. `set -o pipefail` + `grep -q` early exit produced a FALSE failure

The AC27 self-verification ran `! missing_set "$MUTATED_REACHABLE" | grep -qxF "FLOW_RULES.md"`. `grep -q` exits at its first match; the producer's next write then raises **SIGPIPE**, so under `pipefail` the pipeline reports **141** even though the line *was* found — and `!` flips that into the failure branch. With exactly one missing entry the producer finished before `grep -q` exited, so the control passed **by accident**. Defect 1 supplied a second missing entry and the control emitted `"production missing_set did NOT report the omitted FLOW_RULES.md"` — a statement that was simply untrue.

Isolated proof: same producer, `rc=0` direct vs **`rc=141` piped**.

## Fixes

| # | Fix |
|---|---|
| 1 | **Structural docs classification.** `-path './docs/*'` replaces the whole name enumeration. The framework doc surface under `docs/` is **top-level `docs/*.md` only** — exactly what `SYNC_FILES` already declares — so every `docs/<subdir>/**` is a dated record tree. Nothing to maintain, nothing to go dead, and a new doc tree is classified correctly on creation instead of on its first token. |
| 2 | **Pure-bash `has_line()` exact-line membership.** No pipe ⇒ no SIGPIPE ⇒ no false verdict. `missing_set` output is captured into a variable rather than piped into `grep -q`, closing the class twice over. (A quoted `"$2"` inside a `case` pattern is literal, so paths need no escaping.) |
| 3 | **`guard-detects-omission` now drops TWO files and requires BOTH reported.** The control finally exercises multi-entry output — the exact shape that hid defect 2 for as long as it existed. |
| 4 | **New `docs-surface-is-top-level-only` guard** asserts the other half of the structural rule: no allowlisted path may live under a `docs/` subdirectory. Prune side and reach side can no longer silently disagree. |

## Knowledge captured

`docs/problem-catalog/docs-only-commit-broke-content-derived-gate/problem.md` (FR-15). The durable lesson: **the gate must run on the tree you actually push.** For a gate that derives its expected set from the filesystem, there is no such thing as a docs-only change — adding a markdown file IS a change to the gate's input. Two corollaries: prefer a structural rule over an enumerated exclusion list, and treat any assertion that only ever runs in its single-element degenerate case as unproven.
