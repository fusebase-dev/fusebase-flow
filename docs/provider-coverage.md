# Provider coverage: Claude Code and Codex

The core's mechanisms work from provider-neutral signals: files under `state/`, `git`, and the typed return as a file. A provider hook is an extra signal, never the only one (handoff section 4a). This page replaces 5.x's `docs/hook-coverage.md`; it lives in the core repository and is not installed into projects. Status as of the 6.0.0 pass: a fixture is `maintainer/tests/test_scripts.py` or `test_core.py`, run with no audit line and no provider hook wired; "run" means a real project slice on that provider, of which there is none yet for the scripts.

| Element | Provider-neutral form (required on both) | Claude Code adds, when wired | Codex adds, when wired | Status |
|---|---|---|---|---|
| Git hooks: secret scan, protected paths, module size, lint and typecheck | Git pre-commit and commit-msg; identical on both | nothing | nothing | Claude Code: measured in release 1 (27 of 29 blocks). Codex: unproven, no run |
| Deny list and tool-time approvals | Git fallback blocks at commit time | `PreToolUse` on Bash, PowerShell, Edit, Write, MultiEdit, NotebookEdit (`hooks/handlers/pre_tool_use.py`) | `PreToolUse` on Bash | Claude Code: fixture (Wire), no project run. Codex: unproven, no run; edits reach Codex hooks as `apply_patch`, which the handler does not parse, so the tool-time path and secret arms are unenforced on Codex (the git pre-commit covers both) |
| Audit line | none; the audit line is a hook product | `PostToolUse`, `PostToolUseFailure`: tool and call ids and the command's sha256, never its text, no git call (`hooks/handlers/post_tool_use.py`) | `PostToolUse` on Bash; Codex has no failure event | Claude Code: fixture (Wire), no project run. Codex: unproven, no run |

Claude Code: no run. Codex: unproven, no run |

| Hook wiring | `install --wire-hooks`, per declared provider, opt-in; a plain install writes no hook settings | merges into `.claude/settings.json` beside the CLI's entries | merges into `.codex/hooks.json`; Codex asks to trust each project hook; `.codex/config.toml` is never written | Fixture (Wire). `state/status.line` says `wired` when the settings name a handler that exists. Codex: unproven, no run |

Codex support is claimed only after one slice of the first consumer phase runs on Codex through the same core. Until then: Codex: unproven.
