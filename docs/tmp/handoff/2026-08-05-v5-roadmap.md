## 2. Risk-classification contract

### 2.1 Normative result

The classifier has exactly three outcomes:

| Exit | Result | Meaning |
|---:|---|---|
| `0` | `LIGHTWEIGHT` | No Full trigger matched. This is the default. |
| `10` | `FULL` | One or more observable Full triggers matched. |
| `2` | `INPUT_INVALID` | Required machine input is absent, contradictory or unparsable. This blocks with a precise repair message; it is **not** silently converted into Full. |

There is no `UNCERTAIN` outcome and no “in doubt → Full” branch.

The classifier is deterministic over:

1. Base and candidate Git trees.
2. Changed paths, status, line count and component count.
3. Parsed changes to supported manifest/contract files.
4. A minimal change declaration.
5. `policies/risk-classification.yml`.
6. Existing protected-path and secret policy categories.

The actual candidate diff is authoritative. A declaration can add risk; it cannot conceal a diff-derived trigger.

### 2.2 Minimal change declaration

Generated by the agent or CLI, not manually authored by the operator:

```yaml
change_kind: bugfix | feature | maintenance | docs
root_cause: known | unknown | not_applicable
root_cause_ref: path-or-test-id
effects:
  - none
  - auth
  - permission
  - secret
  - migration
  - persistent-data-write
  - public-contract
  - external-side-effect
rollback: git-revert | documented-procedure | none
planned_paths:
  - path/glob
force_full: false
```

Validation rules:

- `bugfix + root_cause: known` requires a resolvable `root_cause_ref`.
- `bugfix + root_cause: unknown` is valid and triggers Full.
- `effects: none` cannot coexist with another effect.
- A diff-derived effect missing from `effects` is a declaration error and blocks.
- `planned_paths` is used before implementation; the staged and CI classifiers recompute from actual paths.
- Documentation-only is not a bypass. It simply has no automatic Full trigger unless it changes a protected/public contract. Final-SHA verification still applies.

This operationalizes the catalog’s explicit “stop and decide the contract” rule without translating missing input into ceremony ([undecided-contract-drives-repeat-defects/problem.md:39](<C:/Users/Pavel/projects/fusebase-flow-publish/fusebase-flow-FuseBase CLI edition/docs/problem-catalog/undecided-contract-drives-repeat-defects/problem.md:39>)).

### 2.3 Full triggers

| Trigger | Observable condition | Source | Downward override |
|---|---|---|---|
| **F01 AUTH_PERMISSION** | A changed path matches configured `auth_permission_globs`; or parsed policy keys alter roles, access, allow/deny, approver or permission behavior; or declaration includes `auth`/`permission`. | Diff + declaration | **Never** |
| **F02 SECRET_CREDENTIAL** | A path belongs to the protected secret/environment category; secret validation code or patterns change; or declaration includes `secret`. | Diff + existing protected-path policy + declaration | **Never** |
| **F03 MIGRATION_DATA** | Added/changed migration, schema, DDL or backfill path; destructive SQL token in a configured migration path; or effect is `migration`/`persistent-data-write`. | Diff + declaration | **Never** |
| **F04 PUBLIC_CONTRACT** | Change to OpenAPI/GraphQL schema, consumer contract, CLI flag schema, package exports, plugin manifest, public config schema, or a configured `public_contract_glob`; or effect is `public-contract`. | Diff parser + declaration | **Never** |
| **F05 RELEASE_SECURITY_UPGRADE** | Change to release/verify CI, approval/command/protected-path/secret policies, hook enforcement, upgrade classifier/materializer, managed manifests or SHA verification. For this repo that includes `hooks/handlers/**`, relevant `hooks/shared/**`, `hooks/git/**`, the four security policies, release/verify workflows and upgrade/materialization scripts. | Exact paths from policy | **Never** |
| **F06 UNKNOWN_ROOT_CAUSE** | `change_kind: bugfix` and `root_cause: unknown`. Missing root-cause fields are invalid input, not Full. | Declaration | **Never** |
| **F07 NON_REVERSIBLE_EXTERNAL** | `rollback: none`; effect is `external-side-effect`; or a deploy operation combines code with a migration, secret, sidecar or external-system mutation. | Declaration + deployment diff | **Never** |
| **F08 PROTECTED_STRUCTURAL** | Delete, rename or mode change of a protected file; edit to a worker-undisturbed path; new executable hook; submodule change; or unreviewable binary change. | Git status/mode + protected-path policy | **Never** for protected paths; binaries may be operator-waived |
| **F09 BLAST_RADIUS** | More than **8** non-generated production files, more than **400** added+deleted production lines, or more than **2** configured components. Generated/vendor/test/docs files are excluded from these counts but remain subject to other triggers. | Diff statistics | Operator may waive |
| **F10 DEPENDENCY_PLATFORM** | New runtime dependency, runtime dependency major-version change, build-system replacement, or supported-platform matrix change. Patch/minor bumps do not trigger unless another rule matches. | Parsed manifests/lockfiles | Operator may waive |
| **F11 FORCE_FULL** | `force_full: true`, or operator explicitly requests Full. | Declaration/operator record | Not applicable |

The size thresholds are initial locked defaults, not agent judgment. They may change only through a reviewed policy commit with measurement evidence.

Configured-but-unmapped paths remain Lightweight unless another trigger matches. That limitation is intentional and honest: a deterministic classifier is not a semantic oracle. Measurement records unmapped production paths so policy coverage can improve without falling back to “doubt.”

### 2.4 Consequences of Full classification

Full does not automatically activate every governance mechanism:

| Matched trigger | Required addition |
|---|---|
| F01–F05, F07, protected F08 | Single `ticket.md`, relevant security/contract verification, independent adversarial review |
| F06 | Root-cause investigation before implementation; implementation may resume when the declaration becomes `known` |
| F09 only | Single `ticket.md` and ordinary code review; adversarial review only if the operator or policy requires it |
| F10 only | Dependency/platform verification and rollback note |
| F11 only | Requirements explicitly selected by the operator |

Both lanes always retain FR-06/FR-07 protection, secret scanning, deterministic tests, exact-SHA release verification and rollback awareness. Lightweight means fewer planning artifacts, not fewer safety rails.

### 2.5 Execution points

1. **Planning:** classify `planned_paths` and declaration.
2. **Pre-commit:** recompute against staged diff. A new hard trigger promotes the change to Full and reports exact trigger IDs.
3. **CI:** recompute against base/candidate trees. CI ignores a self-declared lower lane.
4. **Release preparation:** verify classifier result and verification receipt both refer to the candidate SHA.
5. **Policy change:** changing classifier triggers or override rules is itself F05 Full.

The classifier and tests are direct consumers of the same policy file. No second prose copy is authoritative.

### 2.6 Override contract

- **Upward override:** operator or agent may set `force_full: true`. Reason is recorded, but no additional human confirmation is required.
- **Downward override:** only the operator may waive F09, the non-protected binary arm of F08, or F10.
- F01–F07 and protected-path F08 are not waivable.
- A downward override must contain:

```yaml
risk_override:
  trigger_ids: [F09]
  reason: "Bounded generated adapter split; one runtime component"
  operator_confirmation_ref: "..."
  base_sha: "..."
  diff_digest: "sha256:..."
  expires_at: "..."
```

- Pre-commit and CI reject an override when the base SHA, diff digest, expiry or trigger list no longer matches.
- An agent cannot author its own downward override.
- No global `ignore_risk_classifier` setting exists. Changing policy is the escape route and is itself F05 Full.

## 4. FR-01–FR-27 disposition

The consolidated core is:

1. **Scope and risk are classified from observable facts.**
2. **Evidence and contract precede implementation.**
3. **Changes are atomic and reversible.**
4. **Checks run deterministically on the actual candidate.**
5. **Sensitive paths, secrets and destructive actions fail closed.**
6. **External effects require one explicit, scope-bound human confirmation.**
7. **Risky surfaces receive independent adversarial review.**
8. **Release and live proof bind to the exact published SHA, with rollback defined.**

## 5. What this roadmap must not do

- **Do not remove or weaken the safety kernel.** Adversarial review, exact published-SHA gating, FR-06/FR-07, fail-closed secret scanning, three-way upgrade classification/materialization and the problem catalog remain. They are explicitly protected at [north-star.md:29](<C:/Users/Pavel/projects/fusebase-flow-publish/fusebase-flow-FuseBase CLI edition/docs/north-star.md:29>).

- **Do not translate “Lightweight default” into “all changes are low risk.”** Auth, permissions, secrets, migrations, public contracts, unknown-root-cause bugs and non-reversible effects remain mechanically Full.

- **Do not remove adversarial review because it costs time.** Independent review found substantive blockers after a green 649-test result ([product-review-proposal.md:11](<C:/Users/Pavel/projects/fusebase-flow-publish/fusebase-flow-FuseBase CLI edition/docs/tmp/handoff/2026-08-05-product-review-proposal.md:11>)). The correct optimization is risk routing, not deletion.

- **Do not weaken exact-SHA release gating to eliminate a second gate run.** Move closeout before the final gate and make the final run authoritative.

- **Do not replace the three-way upgrade classifier with overwrite-or-preserve logic.** WorkHub needed seven manual interventions ([workhub-upstream-report.md:7](<C:/Users/Pavel/projects/fusebase-flow-publish/fusebase-flow-FuseBase CLI edition/docs/tmp/handoff/2026-07-30-workhub-upstream-report.md:7>)); Paperclip’s rollback was necessary after the wrong engine overwrote local security work ([paperclip-escalation.md:11](<C:/Users/Pavel/projects/fusebase-flow-publish/fusebase-flow-FuseBase CLI edition/docs/tmp/handoff/2026-08-04-paperclip-escalation.md:11>)).

- **Do not strand WorkHub or Paperclip while simplifying the default.** WorkHub needs reliable cross-platform upgrades; Paperclip needs `artifact_v2` and custom-security-overlay compatibility. They are regression consumers, not the audience used to set ordinary defaults.

- **Do not silently auto-migrate approval validity.** Missing expiry or identity cannot be inferred. Inventory, reject, and explicitly reissue.

- **Do not delete FR-07 technical exception artifacts.** One ordinary deploy decision does not replace path-, action-, SHA- and expiry-bound exceptions.

- **Do not ship a partial shell parser as a regex patch.** The backlog records six semantic failure classes and requires a proper parser/corpus before changing behavior ([command-gate-shell-evasion/backlog.md:40](<C:/Users/Pavel/projects/fusebase-flow-publish/fusebase-flow-FuseBase CLI edition/docs/backlog/command-gate-shell-evasion/backlog.md:40>)).

- **Do not implement single-use approvals before a stable host call ID, atomic consumption and success/failure finalization exist.** Those prerequisites are documented at [approval-single-use-and-replay-resistance/backlog.md:24](<C:/Users/Pavel/projects/fusebase-flow-publish/fusebase-flow-FuseBase CLI edition/docs/backlog/approval-single-use-and-replay-resistance/backlog.md:24>).

- **Do not mechanize role-path separation.** That would turn optional role theater into a structural blocker, and the current proposal depends on prompt-derived role state that can be absent ([role-path-hook-enforcement/backlog.md:5](<C:/Users/Pavel/projects/fusebase-flow-publish/fusebase-flow-FuseBase CLI edition/docs/backlog/role-path-hook-enforcement/backlog.md:5>)).

- **Do not turn FR-27 prose into aggressive timeout reductions.** Gate bounds currently have little headroom and zero deterministic assertions ([gate-bounds-and-liveness/backlog.md:8](<C:/Users/Pavel/projects/fusebase-flow-publish/fusebase-flow-FuseBase CLI edition/docs/backlog/gate-bounds-and-liveness/backlog.md:8>)). Bounds need progress signals, process-group control and 2–3× observed headroom.

- **Do not bulk-rewrite historical specs, handoffs or catalog entries.** Compatibility readers are cheaper and preserve evidence.

- **Do not treat hooks as universal.** Every claim must identify whether it is conditional host enforcement, local Git enforcement, CI enforcement or guidance.

- **Do not use the two atypical consumers as proof of ordinary-consumer value or cost.** They are valuable regression cases, not substitutes for M1.

## 6. Measurement plan

### 6.1 Cheapest honest design

Run a small paired pilot: **four ordinary consumer repositories, four ordinary changes each**.

- First two changes per repository use the v4.7.1 baseline.
- Next two use the new classifier and thin-lane behavior behind a feature flag.
- “Ordinary” means the final diff matches no F01–F10 trigger.
- WorkHub and Paperclip run only as safety/compatibility regressions and are excluded from the ordinary cost sample.
- Sixteen changes are not statistically representative; they are enough to replace “no ordinary consumer measured” with a transparent directional pilot.

Instrumentation is local and opt-in. Classifier, gate and approval commands append content-free events to a gitignored JSONL file; no source text, prompt text, filenames, secrets or user identity are captured. Export requires an explicit redacted-summary command.

### 6.2 Measures and questions

| Measure | Instrument | Question answered |
|---|---|---|
| Human decision count | Count explicit approval/clarification records by ticket and scope; deduplicate retries | Did an ordinary change require more than the North Star’s one human decision? |
| Persistent artifact count/bytes | Count newly created Flow lifecycle files and their byte size | Did the roadmap actually thin artifacts? |
| Handoff/session count | Record handoff creation and context restart events | Is Flow forcing session choreography? |
| Active and elapsed time | Timestamp classify, first edit, gate start/end, approval, completion; report both active tool time and wall time | Is process overhead falling, or merely moving? |
| Gate wall time and silence | Per-command duration, progress interval, timeout/kill result | Are safety checks becoming unusable or opaque? |
| Lane and trigger IDs | Planned result, staged result, CI result, promotion reason, unmapped-path count | Does the classifier route risk correctly? How often does Lightweight promote late? |
| Control outcome | Record control ID and result: pass, block, warning, operator override | Which controls actually changed an outcome? |
| Review yield | Count blocker/major findings and their surface; no narrative content | Does risk-routed adversarial review retain its defect yield? |
| Escape/rollback | CI failure, post-release rollback/revert within seven days, reason category | Did simplification move defects downstream? |
| Consumer rating | One closing text question: “Flow reduced / did not change / increased effort; why?” | Does measured friction match operator experience? |

Instrumentation must work through CLI/classifier/gate entry points, not only optional host hooks; otherwise the sample would reproduce the current enforcement-visibility problem.

### 6.3 Pass thresholds

Proceed from M1 to the breaking artifact/package slices only if:

- At least **75%** of new ordinary changes require no more than one human decision.
- At least **75%** create no more than one persistent lifecycle artifact.
- Median Flow-specific active time falls by at least **30%** against the paired baseline.
- No safety-kernel escape is attributable to Lightweight classification.
- Late promotion from Lightweight to a non-waivable Full trigger is at most **10%**.
- Risk-routed review retains blocker/major yield on triggered surfaces.
- WorkHub upgrade and Paperclip artifact-v2 regression suites remain green.

### 6.4 Roadmap falsifiers

The roadmap is falsified—not merely “needs tuning”—if any of these occurs:

1. **Premise falsified:** the baseline already meets the one-decision/one-artifact target for at least 75% of ordinary changes. The problem is then activation or documentation, not product structure.
2. **Benefit falsified:** median Flow-specific effort falls by less than 30% after classifier and thin-ticket adoption.
3. **Safety falsified:** any secret, protected-path, authorization, migration or release-SHA defect escapes because the simplified lane omitted a retained kernel check.
4. **Classifier falsified:** more than 10% of apparently ordinary changes acquire a non-waivable Full trigger only after implementation starts.
5. **Compatibility falsified:** preserving WorkHub or Paperclip requires maintaining two divergent safety engines rather than a default plus explicit opt-in pack.

If falsified by cost, stop before S5–S9. If falsified by classifier coverage, keep the low-friction objective but revise the observable trigger policy before changing any lane or artifact default.
