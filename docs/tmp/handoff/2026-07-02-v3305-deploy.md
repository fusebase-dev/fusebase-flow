## Post-deploy — FR-14 SINGLE docs commit
One commit `docs(post-deploy): v3.30.5 hook-security hardening (FR-07 + FR-12 fail-closed)`. Add these `docs/problem-catalog/<slug>/problem.md` entries (use `templates/problem-catalog-entry.md`; add a README.md index row for each) — the operator explicitly requested records "so next time we avoid such problems":
- **`security-check-fail-open-class`** (high) — the umbrella lesson. Across v3.30.5, the pre-commit security checks (FR-07 §3 protected-path AND FR-12 §2 secret scan) had MULTIPLE reachable fail-opens, each closed in turn: delete/rename skipped (ACM-only diff-filter → `staged_change_paths` A/C/M/D/R); import/enumeration/`SystemExit(0)`/`except Exception` errors silently passed (→ fail CLOSED with `BaseException`, exit 1 + diagnostic); missing/overridden policy total-disable (→ present+additive-only). Guardrail: a security control must FAIL CLOSED at EVERY reachable load-point; tests must cover the BYPASS and the FAIL-OPEN path, not just the happy path; enumerate the full change set (deletes + rename old+new).
- **`mutable-python-load-point`** (high) — the deepest lesson (the trusted-HEAD pattern). Any security check that LOADS/EXECUTES code, patterns, or config from the WORKING TREE can be neutralized by tampering that working-tree copy (even UNSTAGED, and even via Python startup files `sitecustomize.py`/`usercustomize.py` or a hostile `PYTHONPATH`). Resolution: run security checks from the TRUSTED committed copy (`git show HEAD:` extracted into a fresh `mktemp` dir), under `python3 -S` with a scrubbed env (`unset PYTHONPATH/PYTHONSTARTUP/PYTHONHOME`, `PYTHONNOUSERSITE=1`), with the trusted-vs-fallback decision made by GIT (`git ls-tree HEAD`, shell-side, unforgeable). Guardrail: never trust working-tree code to check working-tree changes.
- **`cwd-on-syspath-under-dash-S`** (high) — the specific tail bug + the two-reviewer catch. `python3 -S -` (reading a script from STDIN) leaves the current directory (the mutable repo root) on `sys.path[0]`; `-S` disables site-packages but does NOT strip CWD. So an UNSTAGED repo-root `pathlib.py` (or a discriminating `yaml.py` shim) shadows a stdlib/site import inside the otherwise-trusted wrapper and can `os._exit(0)` to force a pass — VERIFIED end-to-end (a real AWS key committed to HEAD with the hook saying "all checks passed"). Resolution: run the wrapper as a trusted FILE SCRIPT from the temp dir (`sys.path[0]` = script dir = temp dir, CWD never added — version-independent), + `PYTHONSAFEPATH=1` (3.11+) + in-script scrub via builtin `nt`/`posix` + prepend (not append) site-packages so real PyYAML wins. Guardrail: `-S` is NOT enough; for stdin/`-c` Python the CWD is on the path — prefer a file-script from a trusted dir, or scrub `sys.path` before the first non-builtin import.
- **`adversarial-review-convergence`** (medium) — process lesson. v3.30.5 took TEN convergence rounds because each independent adversarial confirm (Codex companion + a 3-lens Opus panel) found a DEEPER reachable bypass than the last — quality-positive but slow. Signals it was real convergence (not an infinite loop): each round closed a DISTINCT, named mechanism forming a finite ladder of "how working-tree code reaches the interpreter" (file → patterns → policy → exceptions → startup files → env → called-modules → import path); the last two independent reviewers BOTH returned SHIP with zero findings and end-to-end RED→GREEN PoCs. Guardrail: run INDEPENDENT adversarial review (ideally 2+ reviewers) of the ACTUAL code before deploy; converge only when independent reviewers agree and only out-of-model residuals remain; give the operator a transparent per-round heads-up.
- **`msys-git-command-substitution-hang`** (medium) — reliability. A `$(git ls-tree …)` command substitution inside the hook intermittently HANGS under MSYS/Git-Bash (a Windows-native git grandchild holds the captured pipe open past exit → rc=124), the source of gate-timeout flakiness. Resolution: capture git output via FILE REDIRECT (`git … > tmpfile`), the pattern the hook already uses for its prep extractor. (Sibling of `run-tests-never-completes-msys`.)
