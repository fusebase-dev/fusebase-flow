## Context — the finding (deploy-gate confirm, BLOCKER, VERIFIED)
T29-T31 hardened every python invocation with `-S` + controlled PYTHONPATH + trusted-HEAD extraction of the CALLED modules (path_policy for §3, staged_secret_scan+patterns for §2). BUT the §2 (pre-commit ~:153) and §3 (~:392) **main checks run their wrapper Python via `python3 -S -` (STDIN heredoc)**. `-S` disables site-packages; it does NOT remove the current directory from `sys.path`. VERIFIED on this box (Python 3.14.4): `printf 'import sys;print(sys.path[:3])' | python3 -S -` ⇒ `sys.path[0]` = the REPO ROOT (CWD). `pathlib` is NOT builtin (`'pathlib' in sys.builtin_module_names` == False), so:

**Reachable in-model bypass:** an attacker/agent drops an UNSTAGED repo-root `pathlib.py` (or `yaml.py`) containing `import os; os._exit(0)` (or `raise SystemExit(0)`). The §2/§3 heredoc bodies do `from pathlib import Path` (and later `import yaml` at ~:190 / ~:437, after site-packages re-add — repo root still ahead of site-packages) BEFORE any sys.path cleanup and before the guarded trusted-import blocks. `import pathlib` resolves to the malicious repo-root file first → `os._exit(0)` → the `python3 -S -` process exits 0 → the shell treats the check as PASSED → a real secret (§2) or an unapproved protected-path edit (§3) commits unguarded. Same mutable-Python class as the T29 unstaged path_policy tamper, via a mechanism `-S` doesn't cover.

VERIFIED fixes (both work on 3.14): `python3 -S -P -` ⇒ CWD gone; `PYTHONSAFEPATH=1 python3 -S -` ⇒ CWD gone. `-P`/`PYTHONSAFEPATH` are 3.11+ only, so the PORTABLE fix must not depend on them alone.

1. **Codex** — `pathlib.py` shadow: the heredoc's `from pathlib import Path` resolves to a repo-root `pathlib.py` (`os._exit(0)`) before any scrub. (`pathlib` is NOT builtin — verified.)
2. **Opus panel (verified END-TO-END with a real `git commit` landing an AWS key in HEAD)** — `yaml.py` shadow: `_restore_site_packages()` in `hooks/shared/staged_secret_scan.py:~87` uses `sys.path.append(p)`, so real PyYAML lands AFTER the `$ROOT` entry. Both vectors share ONE root cause: the `-S -` stdin invocation leaves the mutable repo root on `sys.path` ahead of stdlib/site. Stripping CWD closes BOTH (pathlib AND yaml AND any other working-tree top-level module). NOTE: repo-root `yaml.py`/`pathlib.py` are NOT FR-07-protected and are untracked — so FR-07-protecting them is NOT the fix (an unstaged/untracked plant still bypasses); the correct fix is to remove the CWD import surface so they are never on the path.

## Scope — ONE coherent commit (strip CWD from every stdin/-c python invocation)

- **PRIMARY fix (portable, all Python versions) — pick the cleanest of these two, applied to EVERY `python3 -S -` (stdin) and any `python3 -S -c` invocation in the hook:**
  - **(A preferred) Run the wrapper as a trusted FILE script, not stdin.** Write each heredoc body to a file INSIDE the already-created trusted temp dir (the one holding the extracted trusted modules) and invoke `python3 -S "$TRUSTED_DIR/<wrapper>.py"`. For a file script, `sys.path[0]` = the script's directory (the trusted temp dir), and CWD is NOT added — so a repo-root `pathlib.py`/`yaml.py` is not on the path at all. No version-dependent flags. Cleanest + fully portable.
  - **(B alternative) In-script sys.path scrub as the FIRST statements of each stdin heredoc, before ANY non-builtin import.** `import sys` (sys is builtin — unshadowable). Get CWD via a BUILTIN os core (`import nt` on Windows / `import posix` on POSIX — both are in `sys.builtin_module_names`, so they cannot be shadowed by a repo-root nt.py/posix.py) → `_cwd = <core>.getcwd()` → `sys.path[:] = [p for p in sys.path if p not in ('', '.', _cwd)]`. Idempotent (no-op if CWD already absent). Do NOT use `del sys.path[0]` (it would wrongly drop the stdlib entry when PYTHONSAFEPATH has already stripped CWD). Then proceed with `from pathlib import Path` etc. — now safe.
- **DEFENSE-IN-DEPTH (add regardless):** add `export PYTHONSAFEPATH=1` to the env-scrub block at the hook top (alongside the T30 `unset PYTHONPATH PYTHONSTARTUP PYTHONHOME` / `PYTHONNOUSERSITE=1`). Effective on 3.11+ (interpreter never puts CWD on sys.path), harmless/ignored on older. Belt-and-suspenders with the primary fix.
- **Audit ALL python invocations:** confirm file-script invocations (`python3 -S <path/to/file.py>`) are SAFE (script-dir on path, not CWD) and need no change; only stdin(`-`)/`-c` invocations need the primary fix. If the PREP extractors use `-c` or `-`, fix them too. Grep-prove: no `python3` invocation in the hook leaves the repo-root/CWD on `sys.path` before its first non-builtin import.
- **Preserve `yaml` import:** `import yaml` (PyYAML, a site-package) must STILL succeed after the fix (site-packages re-added; CWD removed does not remove site-packages). Keep the T31 ordering (`_restore_site_packages()` before `import secret_scanner`/`import yaml`).
- **DEFENSE-IN-DEPTH #2 (panel, verified):** in `hooks/shared/staged_secret_scan.py` `_restore_site_packages()` (~:87), **PREPEND site-packages (`sys.path.insert`) instead of `sys.path.append`** so real PyYAML/stdlib always win over any working-tree shadow even if a CWD-like entry ever survives. The panel verified prepending alone defeats the yaml shim. (This file is trusted-HEAD-extracted, so the change takes effect for post-T32 commits; T32's own commit is protected by the primary CWD strip.) Do not let the prepend shadow the trusted temp dir's OWN modules — order must remain [trusted_temp_dir, site-packages, stdlib], never site-packages ahead of the SEC_IMPORT_DIR/FR07_IMPORT_DIR seed.
- **RELIABILITY #3 (panel lens-2, MSYS robustness — fail-SAFE, same coherent change):** the §2 sentinel loop at `hooks/git/pre-commit:~92` (`$(git ls-tree HEAD -- "$_s")`) and the pre-existing §3 loop at `~:317` use COMMAND SUBSTITUTION around git, which INTERMITTENTLY HANGS under MSYS/Git-Bash (Windows-native git grandchild holds the captured pipe open past exit → rc=124; measured ~3/6 iterations and near-100% of full-hook runs on the saturated host — this is the source of the gate rc=124 timeouts). This is fail-safe (a hung hook only ever BLOCKS), not a security change, but it makes the trusted-HEAD gate actually reliable on the target MSYS platform. Keep the shell/GIT-decided trusted-vs-fallback semantics identical (rc!=0 ⇒ fail closed; rc0+empty ⇒ first-adoption fallback).
