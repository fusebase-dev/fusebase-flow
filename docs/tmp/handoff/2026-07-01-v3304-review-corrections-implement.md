ROOT CAUSE: upgrade.sh runs `set -euo pipefail` (:54) with an ERR trap (:298) but NOT `set -E`. Under `set -e`, a nonzero `wait` (124 timeout OR the child's own failure rc) is a standalone command ⇒ **the shell ABORTS at the `wait`** before `rc=$?` and before control returns to ffhc_run_step's warn/continue (or the critical recovery-hint). Because `set -E` is off, the ERR trap isn't inherited either ⇒ the upgrade exits with the RAW rc, NO warn, NO hint, and (re-mirror runs BEFORE the VERSION write) a HALF-APPLIED tree. The degraded `FFHC_STEP_LIB_OK=0` direct runs `"$@"; rc=$?` at :119/:126 have the identical `set -e` bug.

Now a failed/timed-out OPTIONAL step ⇒ warn+continue rc0; a failed/killed CRITICAL step ⇒ exit 1 WITH the recovery hint. The `wait` abort can no longer escape the function.
