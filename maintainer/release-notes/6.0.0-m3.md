# 6.0.0-m3: the six scripts (pre-release)

The Fusebase Flow 6.0 core with its six scripts in `hooks/local/`: the heartbeat reader, the DONE check, the evidence-row validator, the checks, the slicer and the gate. A re-run of `install` brings them into a 6.0 project.

Needs git, bash and Python 3.10+ with PyYAML. Get this release; the second line installs PyYAML:

```
git clone --depth 1 --branch 6.0.0-m3 https://github.com/fusebase-dev/fusebase-flow.git fusebase-flow-6.0.0-m3
pip install -r fusebase-flow-6.0.0-m3/hooks/requirements.txt
```

**Project on 6.0.0-m2.** Re-run the install. It adds the new files, replaces the Flow files you have not edited, keeps the ones you edited, rewrites its marked blocks in `.gitattributes` and `.gitignore` and `audit/flow-install.json`, and touches nothing else:

```
python fusebase-flow-6.0.0-m3/maintainer/flow.py install --target <your-project> --providers claude,codex
```

If you edited `policies/approval-policy.yml`, the re-run keeps your copy, which has no `gate_rounds`; the gate then allows 2 rounds, the shipped value. Add `--register-reader` to schedule the heartbeat reader every 5 minutes (`schtasks` on Windows, crontab elsewhere); install prints the line and records it in `audit/flow-install.json`. Commit the result as the protected commit `workflows/lifecycle.md` describes: stage it by name, mint with `FF_BOOTSTRAP_TTL_MIN=30 bash hooks/local/write-bootstrap-approval.sh` (the default 15 minutes can run out during a slow pre-commit), commit, then run the same script with `--consume`.

**New project:** the same install command, at the top level of a git repository.

**Project on Flow 5.x.** First run the dry run. It prints what it would remove, replace and add, and what it never touches, and changes nothing. The dry run runs the structural preflight; `--apply` runs the project's lint and typecheck before any change; so a dry run that exits 0 means the migration will go through only once those two also pass by hand. Then run the migration:

```
python fusebase-flow-6.0.0-m3/maintainer/flow.py migrate --target <your-project> --providers claude,codex
python fusebase-flow-6.0.0-m3/maintainer/flow.py migrate --target <your-project> --providers claude,codex --apply --go-ahead
```

`--apply` first checks everything that could stop it, and changes nothing if a check fails. It copies every file it removes or replaces into `.flow-migrate-<UTC time>/`. The migration lands as one commit through the new git hooks, and writes the Flow `.gitignore` block.

**Undo.** The end of `--apply` and the migration report in `docs/flow/ledger.md` print this block with the values filled in. Paste it into Git Bash at the project's top level, as one unit. It checks out the pre-migration commit on a new branch, puts the 5.x git hooks back and restores the untracked files the migration removed or overwrote, from the backup folder. If that folder is gone, the block takes the hooks from the 5.x tree's `hooks/git/` and says so, and those untracked files cannot be restored; if that tree has no `hooks/git/` copies either, it stops before anything changes. It stops at the first step that fails, and your shell stays open. The branch you migrated keeps the migration commit.

```
( set -e
  if [ -d ".flow-migrate-<UTC time>" ]; then :; elif git cat-file -e "<the pre-migration commit>:hooks/git/pre-commit" 2>/dev/null && git cat-file -e "<the pre-migration commit>:hooks/git/commit-msg" 2>/dev/null && git cat-file -e "<the pre-migration commit>:hooks/git/pre-push" 2>/dev/null; then echo "NOTE: the backup folder .flow-migrate-<UTC time>/ is gone: the git hooks come from the 5.x tree's hooks/git/, and the untracked files the migration removed or overwrote cannot be restored"; else echo "STOPPED before any change: the backup folder .flow-migrate-<UTC time>/ is gone, and the pre-migration commit does not hold all three of hooks/git/pre-commit, commit-msg and pre-push to put the 5.x git hooks back from"; false; fi
  git checkout -b flow-5x-<UTC time> <the pre-migration commit>
  for h in pre-commit commit-msg pre-push; do if [ -f ".flow-migrate-<UTC time>/.git-hooks/$h" ]; then cp -p -- ".flow-migrate-<UTC time>/.git-hooks/$h" "$(git rev-parse --git-common-dir)/hooks/$h"; elif [ -d ".flow-migrate-<UTC time>" ]; then rm -f -- "$(git rev-parse --git-common-dir)/hooks/$h"; else git cat-file blob "<the pre-migration commit>:hooks/git/$h" > "$(git rev-parse --git-common-dir)/hooks/$h"; chmod +x -- "$(git rev-parse --git-common-dir)/hooks/$h"; fi; done
  if [ -d ".flow-migrate-<UTC time>" ]; then while IFS= read -r p; do mkdir -p -- "$(dirname -- "$p")"; cp -p -- ".flow-migrate-<UTC time>/$p" "$p"; done < ".flow-migrate-<UTC time>/.migrate/untracked.txt"; fi
)
```

## What is new

| Script | What it does | Lines | Design estimate | Ceiling |
|---|---|---|---|---|
| `hooks/local/reader.py` | `--once` (scheduled) or `--watch`: heartbeat files, the git index, the last commit and `state/` mtimes; writes `state/status.line` and `state/reader/last.json`; alerts on silence | 166 | 60 | 200 |
| `hooks/local/done.py` | A task counts only with a commit carrying exactly its `T<n>` inside its globs, and the builder's return agrees; writes `state/done/<slice>.json` | 78 | 20 | 80 |
| `hooks/local/validate_evidence.py` | One row per criterion; captures hashed, sized and dated after the deploy; FINDING behind a PASS, FLAKY, test-id rows by TAP marker; the minimum evidence class | 214 | 80 | 250 |
| `hooks/local/checks.py` | Four flags on one slice (scope, dependency and config, budget, redundancy) into `state/flags/<slice>.tsv`; `--precision` | 283 | 150 | 300 |
| `hooks/local/slice.py` | One task's slice for a builder; `--brief review\|skeptic\|verdict` for a reader; `BLOCKED-AT-input` | 138 | none | 200 |
| `hooks/local/gate.py` | Runs the three checks, writes `state/gate/<slice>.txt`, counts verdicts against `gate_rounds`, `BLOCKED-AT-gate-budget` with a carry-over list | 111 | none | 120 |
| `hooks/local/lib/flow_docs.py` | The shared reader the six import: git, policies at HEAD, the four documents, the kernel's glob dialect | 173 | none | 250 |

Where a script is more than double its estimate: the reader's extra lines carry the audit line as a fourth signal, the alert state that makes two unchanged runs leave the counters equal, and the in-flight repeat count; the DONE check's carry the returns-file agreement (every task named, each SHA on the branch with its id) and the reason per open task; the validator's carry the run-log reading, the deploy comparison and the FLAKY history over the run index, and the three test-id checks.

Also: `policies/evidence-classes.yml`, the seventh policy (class globs, trivial-tier lists, vendored paths, the run-log markers and the capture floor); `gate_rounds: 2` in `policies/approval-policy.yml` (landed first on 5.x `main` as `731acb69`, the kernel lock updated); the Flow `.gitignore` block (`state/approvals/*` with `.gitkeep` kept, `state/audit/*`, `hooks/**/__pycache__/`, `state/reader/`, `state/status.line`); the lifecycle page and the skills name each script's command where a step was by hand; the core's CI release workflow triggers on 6.x tag names only.

## Thresholds and their provenance

|---|---|---|
| Silence alert (`reader.py`) | 30 min | consumer watchdog 2026-10-14; the transcript floor is 15 min (design section 14) |
| Repeated command (`reader.py`, `checks.py`) | 3 identical hashes in flight | owner seed 2026-10-15; UNCALIBRATED: logged, not an alert, until measured |
| No-commit span (`checks.py`) | 200 tool calls | p99 of 434 between-commit spans, release 1 |
| Orientation (`checks.py`) | 135 tool calls before first work | p99 of 156 working agents, release 1 |
| Slice budget (`checks.py`) | 2x the estimate in minutes or files, with no commit | owner seed 2026-10-15 |
| Duplicate block (`checks.py`) | more than 20 lines | owner seed 2026-10-15; the smallest real row on release 1 was 27 |
| Capture floor (`evidence-classes.yml`) | images 10,240 bytes, other files 32 | a blank 1280x720 PNG is 4,313 bytes, a blank 1920x1080 one 8,559 (zlib level 6) |
| Gate rounds (`approval-policy.yml`) | 2 | adversarial verdict C2-07 |

## Limits

- Not in this pre-release: provider hook wiring (`--wire-hooks`), the 6.0.0 `commit-msg` (`plan:` and `ship:` subjects, the trivial tier), the evidence validator inside the pre-commit. The lifecycle page marks what stays by hand.
- The tool-call counts come from the builder's return file; the audit line is not read for them yet.
- Codex: unproven. Every script works from files and git, the same on both providers, but no slice has run on Codex; `docs/provider-coverage.md` lists each element.

This is a pre-release. CI gates it on Linux; the Windows (Git Bash) run reports but gates nothing until 6.0.0.
