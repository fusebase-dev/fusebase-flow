# 6.0.1 (in progress): the deletions pass, and the behaviour change it rides with

Started by the deletions pass (2026-10-24). No tag for the deletions: they ride with the next behaviour change as 6.0.1, and VERSION stays 6.0.0 until then. This note is finished at that tag, with its upgrade steps tested word for word.

## The 5.x line: frozen, and kernel changes land on core only

The owner's decision of 2026-10-24: the 5.x-first rule for kernel changes is dropped from this pass on. 5.x is frozen at v5.11; projects still on 5.x migrate rather than receive fixes. A kernel change lands on `core` only, and every kernel file's hash in `maintainer/kernel.lock` is updated in the same commit. `maintainer/kernel.lock` and `maintainer/check_kernel_lock.py` state the new rule (T398).

## Owner decisions of 2026-10-25

- **When a tool hook fails:** if a tool hook errors, or gets an event it cannot read, the command still runs, as it does today; T272's preflight covers the case we know of. The first time a hook crash during a command is seen in a real project, this changes to blocking the command.
- **Finding Python:** the hooks keep their own copies of the Python search. `run-handler.sh` differs on purpose, because it must never block a session; `check-module-size.sh` now checks each Python the way the other scripts do (T407), so it no longer runs the Microsoft Store shortcut.
